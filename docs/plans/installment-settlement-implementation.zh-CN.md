# 分期付款计划与关联负债结算：实现与验收

日期：2026-11-18。用户已确认本金方向并授权继续开发。本次实现位于独立 `feat/installment-settlement` 分支，源码基线为研究分支的 `1f27ecc43`；不混入上游更新，不自动合并或部署。

## 已实现行为

在现有定期付款详情页增加分期付款计划，支持首期与常规期数独立本息、末期本金自动补足尾差及自定义末期利息。可以预览全部期数后逐期自定义本金、利息、总额及日期，也可以单独修改未付款项并重算最后一期本金。所有货币计算复用 `Money`，持久化采用整数分。

只有当前执行期绑定既有 SubscriptionPeriods，未来金额明细不提前生成开放周期。首页、小组件、通知及付款预览继续使用原路径；订阅 expectedAmount 在计划推进时同步为当前期金额，避免首期之后仍显示原固定金额。详情页剩余付款合计改为精确累加未付款计划。

关联结算沿用现有每小时自动记录和手动付款入口：

1. 信用卡作为转出账户，以正本金和 expense 方向调用一次现有内部转账服务；服务自动生成分期负债账户的 income 对手腿，两腿共用 transferId，并标记 common_transfer。
2. 同一信用卡另记本期利息，标记 not_transfer，使用指定利息分类。零本金/零利息不生成零额交易。
3. 仅产生上述真实交易；不另记整笔总额支出，不生成借记卡还款，不直接写账户余额。
4. 本金、利息、结算快照、计划状态及后继周期加入同一事务。以订阅行锁、周期状态、generation 和有效结算唯一索引防止重复执行。

撤销必须整体处理该期系统创建的本金两腿和利息；经过原有交易删除服务反向恢复余额，重开原计划。普通交易编辑、删除、批量数据库写入不能局部改动已结算交易。实际借记卡还款有独立 transferId，撤销分期不会删除这笔真实还款。

提前结清校验全部剩余本金，单独记录实际利息/费用，取消未来未付款项；撤销结清恢复原有自定义金额、日期和未付状态。已付款历史不能由修改模板覆盖。

## 账户支持范围

首版支持本人、有效、同币种的 system 手动账户；信用卡和普通独立分期负债都可用负余额表示欠款。转出账户可在计划中选择；已有结算历史后锁定账户、关联模式及总本金。

专用 loan 账户有独立余额重算及 transfer_to_loan 支出统计规则，本版明确拒绝关联；车辆、银行同步、跨用户共享及跨币种关联也明确拒绝。利息应进入实际支出，因此账户整体排除统计时拒绝启用关联结算，不静默覆盖用户全局设置。

启用关联结算时，分期负债的负余额必须精确等于剩余计划本金。若外部交易改变了该余额，自动结算停止并要求对账，避免静默超还。

## 用户操作

1. 创建或打开支出类分期，设置币种、总期数、日期；关联结算前关闭交易匹配规则。
2. 在“分期付款计划”配置本金总额、首期、常规期和末期利息，检查每期本金加利息等于总额。
3. 开启关联，选择信用卡转出账户、独立分期负债转入账户、利息支出分类。保存前可预览全部期数并进入自定义模式。
4. 在现有自动化设置中开启“自动记录付款”，或通过原付款按钮查看本息预览并付款。
5. 修改未付款项使用计划列表“编辑”；撤销使用该付款周期的完整撤销入口。实际信用卡还款继续单独记账。

旧分期没有新计划时完全沿用原行为。存在已付或跳过历史的旧分期不会自动猜测本息并转换；首版要求先独立对账，再为剩余本金建立新分期。新计划禁用跳过和单笔关联/仅标已付；通过延期或编辑未付款日期处理延后。若后期希望支持历史迁移或部分提前偿还，需扩展明确的对账流程。

## 数据与接口

新增增量迁移 `20261118000000-installment-payment-plans.ts`，没有重写旧迁移：

- InstallmentPlans：订阅唯一计划、来源账户、币种、总本金、配置和 revision。
- InstallmentScheduleItems：独立期号、日期、本金、利息、总额、状态、执行周期及 generation。
- InstallmentSettlements：每次有效/已撤销结算、快照和交易 ID。角色与 transferId 保存在快照中，交易 ID 数组建立 GIN 索引；原交易永久撤销后仍保留审计信息，避免外键 SET NULL 丢失记录。
- SubscriptionPeriods 增加 settlementGeneration。编辑未付款项、撤销付款会使旧预览失效。
- 部分唯一索引限制每个周期及金额项只有一次有效结算，另有周期与 generation 唯一约束。
- 数据库触发器保护结算交易的更新/删除；只允许完整撤销事务暂时释放保护。服务层提供明确的操作提示。

REST 均在现有 `/subscriptions/:id` 下：

| 方法及路径                            | 功能                                        |
| ------------------------------------- | ------------------------------------------- |
| GET `/installment-plan`               | 全部计划明细                                |
| POST `/installment-plan/preview`      | 无写入预览                                  |
| PUT `/installment-plan`               | 保存计划，带当前 revision；新建为 0         |
| PUT `/installment-plan/items/:itemId` | 编辑单个未付款项                            |
| POST `/installment-plan/payoff`       | 提前结清，带 revision 与 generation         |
| 现有 `/pay-preview`                   | 返回当期本金、利息、总额、账户和 generation |
| 现有 `/periods/:periodId/pay`         | 计划付款须传 generation，禁用单笔金额覆盖   |
| 现有 `/periods/:periodId/revert`      | 整体撤销结算                                |

新增 MCP：get_installment_plan、preview_installment_plan、save_installment_plan、edit_installment_item、payoff_installment；现有付款工具支持 generation，撤销仍遵循 finance:delete 权限。日期输入采用能表达为 MCP JSON Schema 的字符串，在共享服务中校验并转日期。

## 备份、恢复和删除兼容

新增三张表纳入用户备份注册表和按父级归属解析。恢复按依赖顺序插入，重映射账户、分类、周期、计划、金额项和交易引用。恢复事务内部暂时保持结算为 reverting，完成关联重写后恢复原 settled/reverted 状态；失败整体回滚。

当源账本仍存在、备份恢复到另一用户时，为复制的分期本金重新生成独立 transferId，并同步两腿与结算快照，防止原有全局转账删除逻辑沿旧 transferId 触及源账本。普通账本已有转账行为保持原样。

完整用户数据删除/备份恢复只在已授权的整体事务中清理计划依赖，然后执行既有生命周期。单个分期删除不会悄悄留下仍改变余额的结算交易，已有计划时要求使用计划的撤销/停用路径。
